# Настройка ИИ-помощника зон

Интерфейс ИИ-помощника находится в редакторе «Карта автора». Функция создаёт черновики изменений зон и возвращает их в браузер для проверки. **Она не записывает зоны в базу самостоятельно**: каждое предложение пользователь применяет отдельной кнопкой.

## Вариант без установки программ (рекомендуется)

В репозитории уже есть GitHub Actions workflow, который развернёт функцию и перенесёт секреты в Supabase по нажатию кнопки.

### 1. Создай ключ Gemini

1. Открой [Google AI Studio](https://aistudio.google.com/app/apikey).
2. Создай API key и скопируй его в личный менеджер паролей или временно в защищённое место.
3. Не отправляй ключ в чат, не публикуй его на GitHub и не вставляй в код сайта.

### 2. Создай токен Supabase

1. Открой [Supabase Access Tokens](https://supabase.com/dashboard/account/tokens).
2. Нажми создание нового токена доступа, дай ему понятное имя, например `osint-map-deploy`.
3. Скопируй токен. Это секрет с доступом к управлению Supabase — не отправляй его никому и не добавляй в исходный код.

### 3. Сохрани три GitHub Secrets

1. Открой [настройки Secrets этого репозитория](https://github.com/freeosintmaper/osint-map/settings/secrets/actions).
2. В разделе **Repository secrets** нажимай **New repository secret** и добавь по одному:
   - `SUPABASE_ACCESS_TOKEN` — токен из шага 2.
   - `GEMINI_API_KEY` — ключ из шага 1.
   - `ZONE_AI_ALLOWED_EMAILS` — точный email, которым ты входишь в админ-панель OSINT-карты через Supabase Auth.
3. Для каждого секрета в поле Name вписывай имя слева, а в Secret — значение. Сохраняй каждый по отдельности. Значение email не нужно присылать в чат.

### 4. Запусти развёртывание

1. Открой [GitHub Actions → Deploy zone AI to Supabase](https://github.com/freeosintmaper/osint-map/actions/workflows/deploy-zone-ai.yml).
2. Нажми **Run workflow**, оставь ветку `main` и подтверди запуск.
3. Открой появившийся запуск. Дождись, чтобы все шаги завершились зелёными галочками. Если будет красный шаг — открой его и посмотри сообщение ошибки.

Workflow сам:
- перенесёт ключ Gemini и список разрешённых email в секреты Supabase;
- развернёт серверную функцию `zone-assistant` в проект `zojqbhnwsycqhaiqpgxh`.

Ключ Gemini остаётся в секретах сервера, а не в публичном сайте. Для развёртывания не нужно создавать вручную новую Edge Function в редакторе Supabase Dashboard.

## Вариант через терминал

Если Supabase CLI уже установлен и настроен, можно использовать команды:

```bash
supabase login
supabase link --project-ref zojqbhnwsycqhaiqpgxh
supabase secrets set GEMINI_API_KEY="ВАШ_GEMINI_API_KEY" ZONE_AI_ALLOWED_EMAILS="admin@example.com" GEMINI_MODEL="gemini-3.8-flash"
supabase functions deploy zone-assistant --no-verify-jwt
```

Подставь собственный ключ и email, не коммить их в репозиторий и не вставляй ключ в `index.html`.

## Проверка после развёртывания

1. Открой https://freeosintmaper.github.io/osint-map/ и войди в админ-панель.
2. Выбери «Карта автора» → «ИИ-помощник зон».
3. Введи тестовую команду с явными координатами, например: «Создай серую зону вокруг координат 50.4501, 30.5234 радиусом примерно 5 км».
4. Убедись, что ИИ вернул предложение, а на карте появился пунктирный контур.
5. Проверив результат, можешь нажать «Применить предложение». Если ничего не применять, существующие зоны не изменятся.

Кнопка автоматического анализа использует события за последние 48 часов. Точки ударов, тревог и политические сообщения сами по себе не доказывают изменение контроля территории; функция специально просит модель не выводить границы только из таких точек. Любое предложение нужно сверять с первоисточниками.

Если модель `gemini-3.8-flash` недоступна в твоём API-проекте, измени переменную `GEMINI_MODEL` в файле `.github/workflows/deploy-zone-ai.yml` на модель, доступную твоему API-ключу.

### Если Gemini возвращает 503

Функция повторяет временно неудачный запрос один раз и затем пробует резервную модель `gemini-3.6-flash`. Если обе модели временно перегружены, подожди минуту и попробуй ещё раз. HTTP 503 у Gemini обычно означает временную недоступность сервиса, а не неправильный API-ключ. При 401/403 нужно проверить ключ и доступ проекта; при 429 — лимиты API.
